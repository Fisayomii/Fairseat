# FairSeat service

Fair seating and waiting lists for free meetups. This is the service tier; the interface is
`fairseat-web` (Ufoma Onowho). TeSA Africa capstone, cohort 6, Team 4 side project.

**All people, events and activity in this system are fictional demonstration data.**

## What it does (MVP)

- Organisers create, edit and cancel their own events. Admins can manage any event.
- Attendees sign up. If a seat is free they are **going**; if not, they join a first-come,
  first-served **waiting** list.
- When a seat frees up, the next person waiting is **offered** it for 24 hours. If they do not
  accept in time the offer becomes **offer expired** and the seat goes to the next person.
- My Events shows each attendee's true status. In-platform notices report seat offers, lapsed
  offers, and event changes or cancellations.

## The rules, and where they are enforced

| Rule | Where |
|---|---|
| Confirmed seats never exceed the event's seats | `events.seats_taken` with `CHECK (seats_taken BETWEEN 0 AND seats)`, moved only by `UPDATE … WHERE seats_taken < seats` (`SignupRepository.takeSeat`) |
| One active sign-up per person per event | Partial unique index `uq_signups_active_per_user` |
| Waiting list is first come, first served | `ORDER BY created_at, seq` (identity column as tie-break) |
| Cancelling frees the seat and offers it on | Same transaction (`SignupService.cancel`) |
| Accepting at the expiry instant has one outcome | `… AND offer_expires_at > now()`; at the instant itself it is refused |
| A read never changes data | Reads compute `OFFER_EXPIRED` from the clock; only write paths and the sweeper write it |
| Organisers manage only their own events | `EventService.lockOwned`, tested by calling the service directly |

**If the offer sweeper does not run for an hour** (for example the free host is asleep): reads
still show lapsed offers as expired, and the next sign-up, cancel or accept on that event applies
the expiry before doing anything else. The cost is that the next person waiting gets their offer
later.

## Stack

Java 25, Spring Boot 4.1, Spring Security (JWT resource server, self-issued HS256 tokens,
BCrypt passwords), Spring JDBC (`JdbcClient`), PostgreSQL 17, Liquibase, Testcontainers.
The contract is `contract/openapi.yaml`, linted by Spectral and mocked by Prism.

## Awkward cases in the seed data

23 events, generated by `tools/gen_seed.py`. Times are relative to when the migration ran.

- **Lagos React Meetup**: full, two people waiting.
- **Product Managers' Breakfast**: Gbenga's offer expired and moved on; Halima holds a live offer.
- **Figma to Code Workshop**: Kunle's offer lapsed with nobody touching the event. Reads show it
  expired at once; within a minute of start-up the sweeper passes the seat to Ngozi.
- **Startup Legal Basics**: starts within a day, but its 24-hour offer runs past the start (the
  open design problem).
- **Backend Engineers Lagos**: Amaka cancelled and signed up again; My Events shows her once.
- **Women in Tech Lagos Mixer** and **Hackathon Kickoff**: cancelled, one upcoming and one past.
- Past events, an event with no sign-ups, one with one seat left, one with no description, and
  one with a 180-character title.

## Run locally (PowerShell)

Needs JDK 25, Docker Desktop (for the tests) and a local PostgreSQL 17.

```powershell
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://localhost:5432/fairseat"
$env:SPRING_DATASOURCE_USERNAME = "postgres"
$env:SPRING_DATASOURCE_PASSWORD = "postgres"
$env:ALLOWED_ORIGINS = "http://localhost:5173"
.\mvnw spring-boot:run          # or: mvn spring-boot:run
```

Tests (Testcontainers starts PostgreSQL 17 itself):

```powershell
mvn verify
```

Contract lint and mock:

```powershell
cd contract
npm run lint:contract
npm run mock        # http://localhost:4011
```

## Tests that prove the rules

- `SeatConcurrencyIT`: ten simultaneous sign-ups for two seats give 2 going and 8 waiting; the
  same sign-up sent twice at once records one.
  **Failing run:** in a throwaway commit, delete `AND seats_taken < seats` from
  `SignupRepository.takeSeat` and the `events_seats_taken_range` CHECK from
  `001-core-schema.sql`. The test then reports 10 going.
- `AuthorisationIT`: wrong role and wrong owner, called directly over HTTP. Each fails if the
  check in the service is removed.
- `MondayJourneyIT`: the Monday definition of done end to end, through sign-in.
- `OfferExpiryIT`: a lapsed offer reads as expired without a write, the sweeper moves the seat
  on, and accepting a lapsed offer is refused while the seat still moves on.

## Known limitations

- The offer window is a fixed 24 hours, even close to the event start (decision record pending).
- Tokens last 8 hours with no refresh. An expired token on a public page returns 401; the
  interface should drop it and retry signed out.
- No admin oversight screens, no notice read-marking, no pagination beyond limit and offset.
- Free-tier hosting terms: _to be filled in with what was checked on the provider's own pricing
  page and the date._
